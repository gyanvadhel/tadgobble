# A little launch kitchen

The user wants an empty public collection and a more creative submission experience with broader categories. The existing flat form exposes too many fields at once. A real pending submission must remain in the review queue.

## Plan and review

Keep the established palette: Butter #F9F4A7, Plum #39245A, Lavender #C5B5F5, Tangerine #FF7547, Sky #BFDCF5, Lime #D5F568. Keep Bricolage Grotesque for expressive headings and DM Sans for controls. The purple Gobble remains the guide.

Option A: a one-question-at-a-time conversation. Friendly, but it creates excessive navigation for related fields.

```
Gobble / one question / one input / next
```

Option B (chosen): four short, grouped steps beside a live product ticket. The maker sees their listing take shape while completing related fields together.

```
step navigation: basics / people / details / review
---------------------------------------------------
  live product ticket    |  active step heading
  name + category        |  only this step's fields
  Gobble's small hint    |  optional details folded
                         |  back / continue
---------------------------------------------------
```

Review: preserve the site's identity instead of introducing a generic dashboard wizard. The product ticket is the main playful element; plain input labels and real validation keep submission understandable. Use compact category tiles and audience choices, a pricing choice, platform selections, and optional reviewer context. Finish with an accurate preview and explicit ownership confirmation. Do not invent product capabilities or pricing when optional fields are absent.

The empty collection gets an honest first-submission invitation. Hide discovery filters and random-product actions when no products exist. Archive only the six editorial starter listings and disable automatic seeding by default; retain the submitted product and moderation flow.

## Website cover extension

Use the existing butter/plum/lavender palette and Bricolage/DM Sans typography. The website itself becomes the ticket artwork. Compare an extra mandatory image-upload step with an automatic capture that runs alongside category selection; choose the latter to preserve the short submission flow. Add one cover editor at the top of The details: a 4:3 preview, capture status, upload/retake/remove controls, and concise fallback guidance. Keep optional context collapsed. Use the same chosen image on the discovery row, expanded drawer, product page, and admin review.

```
live ticket: website cover | details: cover + replace / retake
                          | existing optional pricing + context
```

Review against the brief: automatic first, maker override, no extra required form fields. Use an actual captured image, no iframe and no invented product artwork. Preserve listing colors as the surrounding frame. Loading and failures explain what the maker can do. Restrict capture to public web pages and keep unpublished images private to the maker and admin.
