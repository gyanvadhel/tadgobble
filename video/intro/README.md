# tadgobble — A better rabbit hole

The approved 40-second vertical product intro. The word **Gobbler** names a maker who has something to showcase. The original tailless Gobble is drawn from the application's own vector silhouette.

## Deliverables

- `deliverables/tadgobble-intro.mp4` — 1080 × 1920, 60 fps, H.264 / AAC, 40 seconds; captions burned in.
- `deliverables/tadgobble-intro-cover.png` — matching vertical cover frame.
- `deliverables/tadgobble-intro.srt` — editable timed captions.
- `data/intro/master.wav` — final audio mix.
- `data/intro/voice.wav` — conformed AI voiceover.
- `data/intro/score.wav` — original procedural music and sound effects.
- `data/intro/takes/` and `takes.json` — recorded UI frames and time-stamped interactions.
- `docs/INTRO_VIDEO_STORYBOARD.md` — approved script and shot list.

## Open the editing workspace

From the project root:

```powershell
rtk proxy node video/intro/serve.mjs
```

Visit **http://127.0.0.1:4188**. Play with sound, scrub the timeline, jump to shots, or toggle captions. The preview and final render use the same deterministic composition. Change timing, camera paths, colors, typography, and transitions in `composition.js`.

## Rebuild

1. `rtk proxy node video/intro/voice.mjs` generates the voice and word timestamps if missing. It uses `OPENAI_API_KEY` from the environment. No key is written to the project. Existing audio is reused.
2. `rtk proxy node video/intro/audio.mjs` conforms the voice to the approved timeline, synthesizes the original score and sound design, and writes the mix/captions.
3. `rtk proxy node video/intro/prepare.mjs` prepares an isolated demo database, authenticated demo session, and actual website covers.
4. In a separate terminal, run `rtk proxy node video/intro/demo-server.mjs`. This serves the production app build locally at port 3115 using only `data/intro/demo`.
5. `rtk proxy node video/intro/record.mjs` captures the actual application through Chromium screencast frames. It records eased cursor arcs, real clicks, website previews, filtering, saving, and the four-step maker submission. The submitted listing stays pending.
6. Run the editing server above, then `rtk proxy node video/intro/render.mjs` for the final export.

The raw UI capture has a variable frame rate. The final camera, graphics, subtitle springs, and export are rendered at 60 fps. Timing maps compress navigation and typing, then slow at activation and hold the results. A textured WebGL plane gives the screen shallow 3D camera movement; temporal accumulation adds blur on fast moves. FFmpeg assembles the picture and audio with a streaming image pipe.

## Catalog and credits

The video explicitly identifies its populated catalog as a **demo**. It uses real site previews of editorial example products. These examples do not imply partnerships, paid endorsements, user counts, or live listing availability. The production catalog and its Argus listing are not changed. No invented analytics or dashboards are shown.

The maker walkthrough submits tadgobble itself, to the isolated local review queue. The real receipt is filmed after the API succeeds. Local demo credentials and the database are excluded from git and are not served by the editing workspace.

Narration is AI-generated using OpenAI's `gpt-4o-mini-tts` with the Marin voice. Word timing uses `whisper-1`, then is conformed to the edit. The end card discloses the AI voiceover. Implementation references: [speech generation](https://developers.openai.com/api/docs/guides/text-to-speech) and [word timestamps](https://developers.openai.com/api/docs/guides/speech-to-text).

The score and sound effects are generated by `audio.mjs`; no stock music or third-party audio recording is used. Fonts are the app's existing Bricolage Grotesque and DM Sans assets; their license files remain in `public/fonts`.
